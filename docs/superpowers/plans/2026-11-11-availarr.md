# Availarr — Plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** un pont entre l'homelab de B (Radarr/Sonarr sans torrent) et celui de A (Radarr/Sonarr/qBittorrent), qui sert les demandes de B depuis la bibliothèque de A, ou depuis un nouveau téléchargement, puis transfère les fichiers.

**Architecture :** un seul paquet Python `availarr` et deux services.
- `availarr.server` (chez A) expose une API à jeton pour l'agent, un panel admin sur un port séparé, et une boucle de rétention. Il parle à Radarr, Sonarr et qBittorrent de A.
- `availarr.agent` (chez B) se présente comme un indexeur Newznab et un client SABnzbd pour le Radarr/Sonarr de B, et télécharge les fichiers depuis le server avec reprise.
- L'état est stocké dans SQLite (stdlib) de chaque côté. Tout le code est synchrone : FastAPI en `def`, httpx.Client, et des threads pour les boucles.

**Tech Stack :** Python 3.12, FastAPI, uvicorn, httpx, python-multipart, sqlite3 et tomllib (stdlib), pytest. Les tests utilisent `httpx.MockTransport` et `fastapi.testclient.TestClient`.

**Spec :** `docs/superpowers/specs/2026-11-11-availarr-design.md`

## Global Constraints

- Python 3.12. Dépendances runtime **uniquement** : `fastapi`, `uvicorn`, `httpx`, `python-multipart`. Dev : `pytest`.
- Rétention par défaut : suppression **7 jours après la clôture** (livraison ou annulation chez B, `closed_at`) **et** ≥ **3 jours** de seed réel (`seeding_time` qBittorrent). Échec si le titre n'est pas prêt **7 jours** après la demande. Les trois valeurs sont configurables.
- Une unité (film ou épisode) est **protégée** si, au moment de la demande, elle avait un fichier chez A **ou** était surveillée (Monitored). Une unité protégée n'est jamais supprimée.
- Torrent introuvable dans qBittorrent ⇒ seed considéré comme atteint.
- L'agent ne fait que des connexions sortantes vers le server. Côté B, seulement Newznab + SABnzbd, aucune mention de torrent.
- Les clés Radarr/Sonarr/qBittorrent de A ne quittent jamais le server. L'API du server n'expose que : lookup, request, status, file, close.
- Le panel tourne sur un port séparé de l'API, protégé par HTTP Basic (mot de passe `admin_password`). Textes du panel en **français**.
- Les titres de release se terminent par `-Availarr`. 1 Go = `10**9` octets. Les horodatages sont des secondes epoch (`float`).
- Toutes les recherches de B déclenchent un téléchargement chez A (pas de filtrage via Seerr), sauf pour un titre en échec non relancé.

## Review Focus

1. **Transfert coupé en plein fichier** : il doit reprendre à l'octet où il s'était arrêté → `test_download_resumes_from_part` (Task 12).
2. **B relance une recherche sur un titre déjà en cours** : il faut réutiliser le job existant, sans nouvel ajout chez A → `test_request_reuses_active_job` (Task 4).
3. **Redémarrage de l'agent en plein transfert** : le job doit se poursuivre au redémarrage → `test_step_resumes_after_restart` (Task 12).
4. **Profil de B sans correspondance** : aucune release proposée, et un bandeau visible dans le panel → `test_lookup_unmapped_profile_returns_none_and_records` (Task 4), `test_unmapped_banner` (Task 7).
5. **Jeton ou clé API absent ou faux** : réponse refusée, aucune donnée exposée → `test_requires_token` (Task 6), `test_bad_apikey` (Task 10), `test_sab_bad_apikey` (Task 11).

### Task 4: Logique des demandes (`jobs.py`)

**Files:**
- Create: `availarr/server/library.py`, `availarr/server/jobs.py`, `tests/fakes.py`
- Test: `tests/test_jobs.py`

**Interfaces:**
- Consumes: `Item`, `release_title` (Task 1) ; `FileInfo`, `Requirement`, `satisfies`, `file_tags`, `ServerConfig` (Task 2) ; `Job`, `JobStore` (Task 3).
- Produces:
  - `@dataclass Unit(key: str, exists: bool, monitored: bool, file: FileInfo | None)`. La clé vaut `"movie:<tmdb>"` ou `"episode:<tvdb>:<s>:<e>"`. Si l'entrée est absente chez A, `units()` renvoie une seule unité à la clé `item.key()`, avec `exists=False`.
  - `class Library(Protocol)` :
    - `units(item) -> list[Unit]` : pour une saison, seuls les épisodes déjà diffusés.
    - `title(item) -> tuple[str, int | None]`
    - `profile_name(item) -> str | None` : profil actuel chez A, `None` si l'entrée est absente.
    - `ensure(item, profile: str, change_profile: bool) -> bool` : ajoute l'entrée avec `profile` si elle manque, change le profil si `change_profile`, surveille les unités et lance la recherche. Renvoie `True` si l'entrée a été ajoutée.
    - `progress(item) -> float` : entre 0 et 1, 0.0 si rien n'est en file.
    - `hashes(item, since: float) -> list[str]` : en minuscules, imports postérieurs à `since`.
    - `remove(item, unit_keys: list[str], drop_entry: bool) -> None` : supprime les fichiers des unités et les désurveille ; supprime l'entrée si `drop_entry`.
  - `tests/fakes.py` : `FakeLibrary(units: list[Unit], title=("Dune", 2024), profile=None, progress=0.0, hashes=())`, avec les attributs mutables `units/profile/progress/hashes` et les listes enregistrées `ensure_calls: list[tuple[Item, str, bool]]` et `removed: list[tuple[Item, list[str], bool]]`. `FakeQbit(seed: dict[str, int | None])` expose `seeding_seconds(h)` et `deleted: list[str]`.
  - `Jobs(store: JobStore, radarr: Library, sonarr: Library, cfg: ServerConfig, clock=time.time)`, avec `unmapped: set[str]` et `transfer: dict[int, tuple[int, int]]` (octets servis / total, rempli par l'API) :
    - `lib(item) -> Library` : `movie` → radarr, sinon sonarr.
    - `requirement(b_profile) -> Requirement | None` : `cfg.profiles[b_profile]`, sinon `cfg.profiles["default"]`, sinon `None`, et le profil est ajouté à `unmapped`.
    - `lookup(item, b_profile) -> dict | None` : `{"title": str, "size": int}`.
    - `request(item, b_profile, release_title) -> Job`
    - `refresh(job) -> Job`
    - `status(job) -> dict` : `{"state", "progress", "error", "files": [{"index", "name", "size"}]}`.
    - `file_path(job, index) -> tuple[str, int]` : lève `IndexError` si l'index n'existe pas.
    - `close(job, outcome: str) -> None`

Règles (spec) :
- `lookup` : renvoie `None` si le profil n'a pas de correspondance, si `store.failed_for(item)` existe, ou si `units()` est vide. Si toutes les unités satisfont l'exigence, la release reprend le titre via `file_tags` du premier fichier et la somme des tailles réelles. Sinon, la release est synthétique : tags `req.announce`, taille `movie_gb * 10**9` pour un film, `episode_gb * 10**9 * len(units)` pour une série.
- `request` : renvoie `store.active_for(item)` s'il existe. Sinon, `protected = [u.key for u in units if u.file or u.monitored]`. Si toutes les unités satisfont, il n'y a pas d'appel à `ensure` et `added=False`. Sinon : `change = lib.profile_name(item) not in req.a_profiles and lib.profile_name(item) is not None`, puis `added = lib.ensure(item, req.a_profiles[0], change)`. Le job est créé, puis `refresh` est appelé.
- `refresh` (pending) : si toutes les unités de `lib.units(item)` satisfont, le job passe `ready`, avec `ready_at=now`, `units` mis à jour avec les vraies clés et `hashes=lib.hashes(item, created_at)`. Sinon, si `now - created_at >= fail_days * 86400`, il passe `failed` avec `error="Introuvable chez A après N j"`.

- `Gardé 📌` (keep), `jamais 🔒` (entièrement protégé), `Supprimé` (deleted).

### Task 12: Agent — client du server et boucle de transfert

**Files:**
- Create: `availarr/agent/transfer.py`
- Test: `tests/test_transfer.py`

**Interfaces:**
- Consumes: l'API du server (Task 6) ; `AgentStore`, `AgentJob` (Task 10).
- Produces:
  - `ServerClient(base_url: str, token: str, client: httpx.Client | None = None)` : `lookup(item, b_profile) -> dict | None`, `request(item, b_profile, title) -> int`, `status(job_id) -> dict`, `close(job_id, outcome) -> None`, `download(job_id, index, dest: Path, size: int, on_progress: Callable[[int], None]) -> None`. Tous les appels portent `Authorization: Bearer`. Le client a un timeout de 30 s en connexion et aucun timeout en lecture pour les fichiers.
  - `step(store: AgentStore, server: ServerClient) -> None` : un passage sur `store.active()`.

`download` :
- La partie en cours est écrite dans `dest + ".part"`. Si elle existe, on envoie `Range: bytes={taille_part}-`. Avec une réponse 206, on ajoute à la suite ; avec une réponse 200, on tronque et on recommence.
- Le fichier est streamé par blocs de 1 Mio, avec `on_progress(octets_totaux_sur_disque)`.
- Une fois `size` atteint, `.part` est renommé en `dest`. Un fichier `dest` déjà complet est ignoré.

`step`, pour chaque job :
- `st = server.status(id)`. `failed` : le job passe failed avec `fail_message = st["error"]`. `pending` : `phase = st["progress"]`.
- `ready` : le job passe transferring, avec `size = somme des tailles des fichiers`. Chaque fichier est téléchargé dans `storage/name`, et `done` est mis à jour à chaque progression. Une fois tous les fichiers reçus, le job passe completed et on appelle `server.close(id, "delivered")`.
- `httpx.HTTPError` : on journalise et on passe au job suivant, le job reste inchangé.
